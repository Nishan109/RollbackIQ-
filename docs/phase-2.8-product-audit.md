Session-bound reads use RLS. Server actions and privileged RPCs own authorization, with a server-side verified user and role checks. Export authorization is enforced before formatting. The proxy applies private caching to authenticated surfaces. The onboarding checklist needs only existing membership, connection and repository data. The dashboard can use bounded metadata queries instead of fetching report payloads. Keep redirects on fixed internal routes and retain the provider's existing validation and replay protections.

The existing import and Gemini routes enforce minute and concurrency quotas in process memory. Separate Vercel instances have separate counters. Gemini also reserves a database daily budget. The ad hoc SQL route bounds requests and limits concurrency per instance. Audit these boundaries and existing provider Auth limits without adding infrastructure or changing deployment configuration.

Priorities are the team setup path, truthful status and useful dashboard actions, then responsive forms, public help and the release QA gate. Expected changes are in `apps/web/app/{page,layout,auth,team,help}`, shared form/report components and presentation helpers, plus isolated test fixtures and release documentation.
